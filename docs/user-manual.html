1 Getting Started

Prerequisites

  • Node.js 18+ — required to run the development server
  • Jira API Token (Cloud) or Password (Server) — generate a token at https://id.atlassian.com/manage-profile/security/api-tokens
  • Jira Base URL — your organization's Jira instance URL (e.g. https://yourcompany.atlassian.net)

Installation

Clone the repository and install dependencies:

git clone <repository-url>
cd jira-etl-dashboard
npm install

Starting the Application

npm run dev

The dashboard will be available at http://localhost:3000.

💡
For PostgreSQL/Supabase storage, set DATABASE_URL in a .env file and run npm run db:push:pg to initialize the database schema.

First Launch — Connecting to Jira

Before extracting data, you need to configure at least one Jira connection:

  1. Open the app and navigate to Settings → Connections.
  2. Click Add Connection and fill in the form:
    • Name — a friendly label (e.g. "Prod Jira")
    • Base URL — your Jira instance URL
    • Email — your Jira account email
    • API Token — your Atlassian API token
    • Project Keys — comma-separated project keys to scope extractions
  3. Click Test Connection to verify — you'll see the server name, version, and response time.
  4. Click Save. The connection will appear in the connection selector in the top-right header.

3 Data Center

3.1 Jira Extraction

The Jira Extraction panel is where you query Jira for ticket data and build your master dataset. It provides a powerful yet easy-to-use interface for ETL operations.

JQL Query Editor

Enter a JQL (Jira Query Language) expression in the text area to define which tickets to extract. For example:

project = "PROJ" AND status changed AFTER -30d

You can save, load, and delete frequently used queries for quick reuse.

Date Range

Set the extraction period using the From and To date pickers. Quick presets are available for common ranges:

Since Yesterday

Excludes anything older than yesterday

Last 7 / 30 / 90 / 365 Days

Rolling window from today

Custom Days Back

Enter any number of days for a custom rolling window

Extraction Options

  • Update Only Mode — Toggle to upsert existing tickets without deleting old ones. Uses the updated field for incremental syncing.
  • Custom Extract Fields — Expand the panel to add custom Jira field IDs (e.g. for "Issue Owner Team"). Use the Discover button to auto-fetch available custom fields from your Jira instance.
  • Scheduled Polling — Enable automatic data fetching at intervals from 1 minute to 4 hours. Shows last run time, next run time, and a live indicator badge.

Running an Extraction

  1. Select a Jira connection from the header dropdown.
  2. Enter a JQL query or select a saved query.
  3. Set the date range using the pickers or quick presets.
  4. Optionally enable Update Only Mode or configure custom fields.
  5. Click Run Jira Extraction. Progress will be shown as tickets are fetched.

Extraction Results

After extraction, results appear in a card showing:

  • Summary stats — Total extracted, resolved, open, oldest ticket date, newest ticket date
  • Ticket list — Searchable, sortable (by key, created, updated), filterable by status. Each ticket links directly to Jira.

Master Dataset

The Master Dataset accumulates tickets across all extractions. It shows total unique tickets, date range, and last update time. Use Show All Tickets to browse the full dataset, or Clear Master Dataset to reset.

3.2 Data Export

The Data Export panel lets you push processed data out of the dashboard in two modes:

File Export

  • Choose data type: KPIs, Raw Tickets, or Both
  • Download as JSON or CSV
  • Select a German state/region for holiday-aware calculations

Database Sync

  • Toggle to Database Sync mode to push data to a configured PostgreSQL / Supabase instance
  • Select the target database from your saved connections
  • Click Push to Database — the row count is displayed after completion
ℹ️
Database sync is designed for Metabase integration. Push your KPI results to PostgreSQL so you can build Metabase dashboards on top of the data.

The Plugins Configuration panel controls which KPI metrics are calculated and how they appear on the dashboard.

KPI Plugin Registry

The left column shows all available plugins grouped by category:

⏱️

Average processing time, first response time, resolution time (6 plugins)

📈

🎯

SLA

SLA compliance, SLA by status, SLA breach rate (4 plugins)

🔄

Turnaround time by status, total turnaround (2 plugins)

✅

Reopened tickets, reopen rate (2 plugins)

👤

Tickets by assignee, open by assignee, workload (3 plugins)

📊

Trending metrics over time with 7 plugins for processing, throughput, and SLA trends

User-created plugins using DSL or JavaScript

Toggle checkboxes to enable/disable plugins. Star plugins as favorites. Use search and filter tabs (All / Active / Favorites) to find plugins quickly.

Widget Display Order

The right column shows the display order of active, non-time-series widgets. Use drag-and-drop (via the grip handle) to reorder how widgets appear on the dashboard.

Custom Plugins

Create your own KPI plugins using the Plugin Builder:

  • DSL Mode — Select a metric type (Count, Average, Sum, Percentage, Time-to-X), set filters, and the formula is auto-generated.
  • JavaScript Mode — Write full custom calculation logic with access to ticket data, changelogs, and settings.

Set a category and unit for the plugin, then save. Custom plugins are hot-reloaded automatically.

SLA Targets by Status

  • Set comment rules: "Assignee only" (SLA clock resets only on assignee comments) or "Anyone" (any comment resets the clock)
  • Use "Detect Statuses from Data" to auto-discover statuses from your master dataset
  • Configure SLA target hours per status

KPI Alert Thresholds

Configure warning and critical thresholds for each plugin:

  • Operator: > (greater than) or < (less than)
  • Warning value — triggers amber alert badge
  • Critical value — triggers red alert badge with pulse animation

4.3 Holidays Calendar

The Holidays Calendar shows German national and regional holidays used for business-hour KPI calculations.

  • Year selector — choose the year to display
  • State/Region selector — select a German state to see its regional holidays
  • Two-column layout: National holidays (apply to all states) and Regional holidays (state-specific)
  • Each entry shows the holiday name, local name, and date
💡
KPI calculations automatically exclude German holidays and weekends when computing business-hour metrics. Make sure the correct state is selected in both the Holidays panel and the KPI Calculation Defaults.

5.2 Storage

The Storage panel manages where your extracted data is persisted.

Storage Types

StorageDescription
Local SQLite Embedded database (dev.db). No configuration needed — works out of the box. Best for development and single-user setups.
PostgreSQL / Supabase External database for shared access, Metabase integration, or production deployments. Configure host, port, database, username, password, SSL mode, schema, and table.

PostgreSQL Management

  • Add/Edit/Delete PostgreSQL backend connections
  • Test connectivity before saving
  • Set as Primary to promote any saved PostgreSQL backend as the active storage

Session Persistence

  • Auto-save after extraction — automatically persist results after each extraction
  • Auto-restore on page load — reload the master dataset when reopening the app
  • Auto-cleanup — remove old data after 7, 30, or 90 days, or never

Storage Usage

View statistics including total extractions, total tickets, database size, and per-connection breakdowns. Use Clear Orphaned Data to clean up disconnected records, or Clear All Data for a full reset.

6 Advanced Features

6.1 Saved Views

The View Manager lets you save and restore complete dashboard states. Each saved view captures:

  • Date range and period preset
  • Active filters (JQL and dimension filters)
  • Widget layout and collapse states
  • Chart configurations
  1. Configure the dashboard with your desired filters, dates, and layout.
  2. Click the View Manager button in the controls bar.
  3. Click Save Current View and give it a name (e.g. "Sprint 24 Review").
  4. Set a view as Default to auto-load it on page open.
  5. Enable Auto-Save to persist changes with a 3-second debounce.
💡
Period presets are smart — a "1Y" view saved today will recalculate dates relative to when it's loaded, not when it was saved.

7 Troubleshooting & FAQ

Frequently Asked Questions

Why is my extraction returning no tickets?

  • Check that the JQL query is valid — test it directly in Jira first
  • Verify the date range covers the period when tickets were created or updated
  • Ensure the project keys in your connection match the projects you're querying

Why do KPI calculations seem incorrect?

  • Check the German state setting in both Holidays Calendar and KPI Calculation Defaults — holidays must match your team's location
  • Verify work hours (start/end) in the Plugins Configuration defaults
  • Ensure your SLA targets are configured if using SLA plugins
  • Check the comment rule setting — "Assignee only" vs "Anyone" significantly affects first-response SLA metrics

How do I reset the dashboard?

  • Use the Clear Master Dataset button in the Jira Extraction panel
  • Use the Clear All Data button in Settings → Storage
  • Or Export/Import configuration in Settings → Configuration to restore a known-good state

Can I use this with Jira Server (on-premise)?

Yes. The dashboard supports both Jira Cloud (using API tokens) and Jira Server/Data Center (using username + password). Enter your server's base URL and credentials in the Connections panel.

Common Issues

IssueSolution
Rate limit errors during extraction Increase the delay or decrease max requests/min in Settings → Configuration → Rate Limiting. Switch backoff strategy to Exponential.
Connection test fails Verify the base URL, email, and API token. Check network access and firewall rules. Ensure the account has API access permissions.
PostgreSQL sync fails Verify the DATABASE_URL in .env. Run npm run db:push:pg to ensure the schema is up to date. Check SSL mode settings.
Dashboard shows "No Data" Run a Jira extraction first. Check that the master dataset is populated. Verify the date range covers available data.
Custom plugin not appearing Ensure the plugin file is in the correct directory. Check for syntax errors — custom plugins are error-isolated and will silently fail if invalid.
🔴
If you encounter an issue not covered here, check the docs/ directory for detailed guides on Electron builds, JIRA field configuration, and custom plugins.
